GroundWorkAI

Street imagery to actionable road repair reports.

Exploring how computer vision can help local governments identify road damage and coordinate repairs.

Try the demo ↗
Tools
React, Leaflet, Python, FastAPI, Ultralytics YOLO, SQLite, Mapillary

01

Context

GroundworkAI is a team project my team built for DubHacks 2026. We explored how street imagery and computer vision could help identify road damage and turn potential issues into reports that people can review and act on.

The project uses detection, map inspection, and repair coordination and turns it all into one workflow. The goal is to support safer, more accessible streets by helping local governments find and organize potential maintenance.

02

Problem

Finding a crack or pothole is only the first step toward repairing it. A report also needs evidence, a location, a review decision, and a way to hand the issue off to the people doing the work.

We approached this as a workflow problem: how could an image based detection become a repair task without losing the information needed to evaluate it? An AI model cannot soley predict whether a defect needs repair or how urgently a crew should respond.

03

Solution

GroundworkAI connects AI assisted detection with human review. Potential defects appear on a map, where reviewers can inspect the source image, check the highlighted damage, adjust the estimated location, and assign a repair priority.

Discover and detect

In live mode, users select a neighborhood on the map. A Python backend discovers Mapillary imagery in that area and runs a YOLO model to identify potential potholes and several types of cracks. Findings are saved as pending issues rather than automatically verified reports.

Review the evidence

Each issue includes an image with a bounding box, model confidence, an estimated location, and a link to its Mapillary source. Reviewers can update the review status and correct coordinates. Repair priority starts unassigned and is chosen by a person, keeping model confidence separate from urgency.

Coordinate the repair

A coordinator can create a work order from a verified issue and assign it to a crew member. The work order view lets the team track progress while retaining the original evidence and location. Search, filters, and CSV export help organize the issues being reviewed.

04

Product

The prototype includes a React dashboard with a Leaflet map, issue details, review controls, and a work order view. The live workflow uses FastAPI and SQLite to process imagery and preserve review decisions.

A repeatable demo

The default demo uses five saved Mapillary images with actual stored model predictions for cracks. This lets someone explore the review and work order workflow without running the model or configuring an API token.

What the prototype demonstrates

GroundworkAI demonstrates a path from a potential defect to a reviewed issue and an assigned repair task. The saved findings are model predictions, not verified field reports, and their locations remain estimates. The prototype does not establish detection accuracy or real-world repair outcomes.

The central design decision is to keep people involved at the points where judgment matters: confirming the evidence, setting priority, and coordinating the response.

05

So whats next?

Since we only had 24 hours to build GroundWorkAI, there are still some limitations. For now, it runs exclusively on sample data because of our limited time and resources. With more time, we'd love to train and improve our model using a larger, more diverse dataset to make it more accurate and useful in real scenarios.
